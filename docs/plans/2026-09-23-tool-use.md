```rust
/// Emit the stored JSON text as JSON rather than as a quoted string.
fn serialize_raw_json<S: serde::Serializer>(json: &str, serializer: S) -> Result<S::Ok, S::Error> {
    let raw = serde_json::value::RawValue::from_string(json.to_owned())
        .map_err(serde::ser::Error::custom)?;
    raw.serialize(serializer)
}

/// Take a JSON value back as its own text, unparsed.
fn deserialize_raw_json<'de, D: serde::Deserializer<'de>>(
    deserializer: D,
) -> Result<String, D::Error> {
    let raw: Box<serde_json::value::RawValue> = Deserialize::deserialize(deserializer)?;
    Ok(raw.get().to_owned())
}
```

```rust
#[derive(Debug, Clone, Copy, Serialize)]
pub struct ToolDefinition {
    pub name: &'static str,
    /// Prescriptive about *when* to call it, not only what it does -- the
    /// description is the only thing steering the model's should-call
    /// decision, and recent models reach for tools conservatively.
    pub description: &'static str,
    pub input_schema: fn() -> serde_json::Value,
}

/// Whether the model may call a tool, must, or must not.
#[derive(Debug, Clone, Copy, Serialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum ToolChoice {
    Auto,
    None,
    Tool { name: &'static str },
}
```

`input_schema` is a function pointer because `serde_json::Value` is not
constructible in a `const`. If that reads badly at the call site, make
`ToolDefinition` an owned struct built by a `definition()` function instead --
either is fine, but do not reach for `lazy_static`.

**What shipped, and why the sketch above could not.** The sketch is left as
written because what it asked for is part of the record. It does not compile.
Its premise is right and its conclusion is not: `Value` indeed cannot be built
in a `const`, but a `fn() -> Value` field cannot be `Serialize` either, since
function pointers do not implement it. `#[derive(Serialize)]` on that struct
fails, so the choice was never between the two shapes offered here.

`input_schema` shipped as `&'static str` holding the schema's JSON text,
written out through `tree::serialize_raw_json` -- the same writer
`ToolUse::input` uses, made `pub(crate)` for it. Text beat the owned-struct
alternative for a reason the sketch could not have anticipated: `&'static str`
fields keep `ToolDefinition` `Copy`, which is what lets `Request` borrow
`&'a [ToolDefinition]` without a lifetime of its own. It also reuses the
decision this crate had already made about holding model-facing JSON as bytes
rather than parsing and reserializing it.

The cost is that a schema is unvalidated text until something serializes it.
That is paid in Task 9, which is where a real schema first exists.

On `Request`:

```rust
    #[serde(skip_serializing_if = "<[_]>::is_empty")]
    tools: &'a [ToolDefinition],
    #[serde(skip_serializing_if = "Option::is_none")]
    tool_choice: Option<ToolChoice>,
```

and in `Request::new(messages, tools, choice)`, set `tool_choice: (!tools.is_empty()).then_some(choice)` -- the two fields travel together or not at all.

`Api::send` grows `tools: &[ToolDefinition]` and `choice: ToolChoice` before `on_block`. Four parameters plus `self`, within the house limit.

**Step 3: Implement**

```rust
pub enum AppendError {
    UnknownParent,
    /// A `tool_use` under a user node, or a `tool_result` under an assistant
    /// one. The role a block belongs to is the API's, not this tree's.
    WrongRole { block: &'static str, expected: Role },
    /// A user block that is not a `tool_result`, hung where calls are still
    /// outstanding. Permanently unsendable: ancestors never change, so no
    /// later append can rescue this branch.
    InterjectedUnderToolUse { unanswered: Vec<String> },
    /// A `tool_result` answering a call that is not outstanding -- never made,
    /// made in another turn, or already answered.
    UnmatchedToolResult { tool_use_id: String },
}
```

The one query both checks need:

```rust
    /// The ids of calls made in the assistant run at `tip` and not yet
    /// answered in the user run below it.
    ///
    /// Empty for a branch with no call in its last turn, which is every
    /// branch this crate held before tools existed.
    fn unanswered(&self, tip: NodeId) -> Option<Vec<String>> {
        let path = self.path(tip)?;

        // The trailing user run holds the answers so far; the assistant run
        // above it holds the calls. Walking from the tip means one pass and
        // no scan of the branch above the last turn boundary.
        let mut answered = Vec::new();
        let mut calls = Vec::new();
        let mut seen_assistant = false;
        for id in path.iter().rev() {
            let node = self.node(*id)?;
            match (node.role, &node.block) {
                (Role::User, ContentBlock::ToolResult { tool_use_id, .. }) if !seen_assistant => {
                    answered.push(tool_use_id.clone());
```
